### 1. Second Screen Mode

So far, the Focus Points plugin has been running in Single Screen mode, which means that the plugin window is attached to Lightroom. While this window is open, Lightroom cannot be used.

V3.5 introduces a new way of using the plugin: Second Screen mode. This mode removes the limitation that Lightroom cannot be used while the plugin is running. When a different image is selected in Lightroom, the plugin automatically calculates and displays the corresponding focus points.

This feature is particularly useful in a multi-screen setup. For example, Lightroom could be used on one screen while Focus Points is displayed on another. Focus Points would then automatically respond to changes in the Lightroom selection. 

<img src="images/SecondScreen%201.jpg" alt="Second Screen 1" style="width: 1000px;"/>

However, Second Screen mode can also be useful for single-monitor setups. When checking the focus points for multiple photos, you are not restricted to using the Previous and Next keys. Instead, you can scroll through your Lightroom filmstrip or grid and select the photos you want. You can also alter the plugin settings without having to close and restart the plugin explicitly: 

<img src="images/SecondScreen%202.jpg" alt="Second Screen 2" style="width: 1000px;"/>

Although the plugin largely retains its look and feel in Second Screen mode, there are a few important differences worth noting:

1. Interaction between the plugin and Lightroom can impact use of keyboard shortcuts  
In Second Screen mode, the plugin runs in an independent window. After opening this window and reopening it for a different image, the plugin window gets the keyboard focus and takes it away from Lightroom. This means if you want to continue working in Lightroom using keyboard shortcuts you need to first click on Lightroom with the mouse. Note that this applies only when the current image is changed. 

2. The plugin window has a fixed width.  
The Second Screen window remembers its position and size, which is particularly useful in a dual-screen setup. To provide a stable screen position and size when displaying images with different aspect ratios, a fixed area is reserved for the photo view when running in Second Screen mode. The image is centered within this area, while the information panel remains aligned near the right edge of the window.

3. Display mode  
When using the plugin in display mode Preview Image, it will immediately use Export Image in Develop module. This is necessary because Lightroom's preview generation is not sufficiently reliable in the Develop module for the plugin's requirements. 

Configuration:

To allow choosing between the two operating modes, the plugin adds a Second Screen option to the current configuration:

<img src="images/SecondScreen Options.jpg" alt="Second Screen Options" style="width: 600px;"/>

When the Second Screen option is enabled, Focus Points opens in a separate window. The size of this window is determined by the Size of plugin window and Aspect ratio settings.

The link will provide quick access to the description of the feature.

Note: The Second Screen window remembers its last position and size. When changing the display size (S / M / L / XL / XXL), the dialog content may temporarily occupy less space than the current window size. This can result in additional empty margins on the right or bottom of the window. These can be removed by simply resizing the window manually once. The adjusted size will again be remembered automatically.

When the Second Screen option is disabled (the default setting), the plugin continues to operate in Single Screen mode as before.

**Limitation on macOS**

Second Screen mode can be chosen regardless of the operating system. On macOS however, the plugin currently remembers the correct position on the screen when reopening, but not the correct screen. When you drag the plugin window to a secondary screen and select another image it will reopen on the primary screen.  A bug report has been filed with Adobe.

If you find this feature relevant, **please vote for this bug report** to increase its priority and improve its chances of being fixed:
https://community.adobe.com/bug-reports-674/p-mac-sdk-floating-dialog-does-not-reopen-on-second-screen-1628255




### 2. Display Modes

What are display modes?

In short, the display mode determines how the image is rendered, allowing markings to be overlaid.

The following display modes are supported in V3.5:

**'Direct View'**. Displays the photo directly through Lightroom's internal Develop rendering engine, overlaying it with icons that visualize the corners of the marking rectangles. Direct View automatically reflects Lightroom edits in real time. It acts as a mirror to what Lightroom displays in the Develop module.

**'Preview Image'**. Retrieves a preview image from Lightroom's preview cache, writes it to a temporary JPEG file, and enhances the image with markings. This mode depends on Lightroom's preview cache and may therefore be affected by the availability of previews or the timing of their refresh.

**'Export Image'**.  Uses Lightroom's Export feature to save an image as a JPEG file to the hard drive. It's not the fastest, but it's rock-solid and reliable.


The following table summarizes the characteristics of the available display modes:

| Mode | Platform | Advantages | Limitations |
|----------------|----------|------------|-------------|
| **Direct&nbsp;View<sup>1</sup>** | macOS, Windows<sup>3</sup> |  Fastest startup, live updates while editing | In Library, the image may appear after a short rendering delay while Lightroom renders it |
| **Preview&nbsp;Image<sup>2</sup>** | Windows, macOS<sup>4</sup> |  Usually fast when a Lightroom preview already exists | Performance depends on Lightroom's preview cache |
| **Export&nbsp;Image<sup>2</sup>** | Windows, macOS<sup>4</sup> | Always produces a reliable image | Typically slower when a Lightroom preview already exists, but often faster when Lightroom first needs to build a preview. |

<sup>1</sup> Uses corner markers for focus points. 
<sup>2</sup> Uses full rectangle overlays. 
<sup>3</sup> Currently experimental on Windows due to a Lightroom SDK issue affecting transparent overlays. [#393](https://github.com/FocusPointsLrC/Focus-Points/issues/393)
<sup>4</sup> To be implemented on macOS [394](https://github.com/FocusPointsLrC/Focus-Points/issues/394)

The following table summarizes the characteristics of the available display modes:

| Mode | Advantages | Limitations |
|----------------|------------|-------------|
| **Direct&nbsp;View** | Fastest startup, live updates while editing | In Library, the image may appear after a short rendering delay while Lightroom renders it |
| **Preview&nbsp;Image** | Usually fast when a Lightroom preview already exists | Performance depends on Lightroom's preview cache |
| **Export&nbsp;Image** | Always produces a reliable image | Slower than Preview Image when a preview exists, otherwise often faster |

**Note:** Direct View uses corner markers for focus points. Preview Image and Export Image use full rectangle overlays.

**Tip:** Each display mode has its own strengths. Direct View provides the fastest, most responsive display while editing. Preview Image and Export Image provide full rectangle overlays. The long-term goal is to make all three modes available on both macOS and Windows, allowing you to switch between them at any time and use the mode that best suits your current task.


### 3. Direct View on Windows

V3.5 introduces Direct View to Windows users. Direct View has been available on macOS since earlier versions. Unlike the Preview Image and Export Image modes, Direct View displays Lightroom's own rendered image directly, without creating a temporary JPEG on disk. This has two major advantages:

- significantly faster window opening
- immediate updates while editing the photo

These characteristics make Direct View particularly useful when using the plugin in Second Screen mode.

Direct View is available Windows but unfortunately, it's not yet perfect.   
Investigation indicates that transparent PNG overlays (the corner icons) are not composited correctly in overlapping SDK views, causing visible rectangular artefacts around overlay graphics. A bug report has been filed with Adobe. 

If you find this feature relevant, **please vote for this bug report** to increase its priority and improve its chances of being fixed:
