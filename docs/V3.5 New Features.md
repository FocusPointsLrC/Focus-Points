### Second Screen Mode

So far, the Focus Points plugin has been running in Single Screen mode, which means that the plugin window is attached to Lightroom. While this window is open, Lightroom cannot be used.

V3.5 introduces a new way of using the plugin: Second Screen mode. This mode removes the limitation that Lightroom cannot be used while the plugin is running. When a different image is selected in Lightroom, the plugin automatically calculates and displays the corresponding focus points.

This feature is particularly useful in a multi-screen setup. For example, Lightroom could be used on one screen while Focus Points is displayed on another. Focus Points would then automatically respond to changes in the Lightroom selection. 

<img src="images/SecondScreen%201.jpg" alt="Second Screen 1" style="width: 1000px;"/>

However, Second Screen mode can also be useful for single-monitor setups. When checking the focus points for multiple photos, you are not restricted to using the Previous and Next keys. Instead, you can scroll through your Lightroom filmstrip or grid and select the photos you want. You can also alter the plugin settings without having to close and restart the plugin explicitly: 

<img src="images/SecondScreen%202.jpg" alt="Second Screen 2" style="width: 1000px;"/>

Although the plugin largely retains its look and feel in Second Screen mode, there are a few important differences worth noting:

1. Interaction between the plugin and Lightroom can impact use of keyboard shortcuts  
In Second Screen mode, the plugin runs in an independent window. After opening this window and reopening it for a different image, the plugin window gets the focus and takes it away from Lightroom. This means if you want to continue working in Lightroom using keyboard shortcuts you need to first click on Lightroom with the mouse. Note that this applies only when the current image is changed. 

2. The plugin window has a fixed width.
The Second Screen window remembers its position and size, which is particularly useful in a dual-screen setup. To provide a stable screen position and size when displaying images with different aspect ratios, a fixed area is reserved for the photo view. The image is centered within this area, while the information panel remains aligned near the right edge of the window.

Exporting is necessary because Lightroom's preview generation is not sufficiently reliable in the Develop module for the plugin's requirements. Previously, this limitation was worked around by temporarily switching from the Develop module to the Library module. In Second Screen mode, however, such automatic module switching is not practical because the user continues working in Lightroom while the plugin updates independently.

Configuration:

To allow users to choose between the two operating modes, the plugin adds a Second Screen option to the current configuration:

Image

When the Second Screen option is enabled, Focus Points opens in a separate window. The size of this window is determined by the Size of plugin window and Aspect ratio settings.

Note: The Second Screen window remembers its last position and size. When changing the display size (S / M / L / XL / XXL), the dialog content may temporarily occupy less space than the current window size. This can result in additional empty margins on the right or bottom of the window. These can be removed by simply resizing the window manually once. The adjusted size will again be remembered automatically.

When the Second Screen option is disabled (the default setting), the plugin continues to operate in Single Screen mode as before.


### Display Modes

The introduction of multiple display methods is primarily intended to improve reliability in Second Screen mode, where the Photo View remains open while Lightroom selection and develop settings change.

The Photo View (1) is the part of the plugin window that displays the selected photo together with focus point, face detection, or subject detection overlays:

<img src="images/User%20Interface.jpg" alt="User Interface" style="width: 1000px;"/>

For historical reasons, the plugin uses different methods on macOS and Windows to display the photo with the markings:

**macOS** uses the **'Direct view'** method. This method displays the photo directly through Lightroom's internal rendering engine and overlays it with icons that visualize the corners of the marking rectangles. Direct View is the only display method that automatically reflects crop and develop changes while the Photo View remains open.

The 'Direct View' method currently does not work correctly on Windows. Investigation indicates that transparent PNG overlays are not composited correctly in overlapping SDK views, causing visible rectangular artefacts around overlay graphics. A bug report has been filed with Adobe. If you find this feature relevant, **please vote for this bug report** to increase its priority and improve its chances of being fixed:
https://community.adobe.com/bug-reports-674/p-windows-sdk-transparent-png-overlays-do-not-composite-correctly-in-overlapping-layouts-1628087

On **Windows**, the plugin retrieves a **'Preview image'**, writes it to a temporary JPG file and uses a third-party tool to draw markings onto these image files. This method depends on Lightroom's preview cache and may therefore be affected by preview availability or refresh timing. It does not work reliably when used from the Develop module.

When the plugin is operating in 'Second Screen' mode, it sits on a secondary display and automatically responds to changes in the Lightroom selection. To make this work reliably on Windows and in the Develop module, a third display method, **'Exported Image'**, will be offered. Like 'Preview Image', it exports a JPG image of the selected photo to disk and adds the required markings to that image. The difference is how the base image is obtained. 'Preview Image' uses Lightroom's preview cache, while 'Exported Image' creates a fresh rendering of the selected photo using Lightroom's export mechanism. 'Exported Image' may be slower than 'Preview Image', but it is more reliable as it doesn't depend on LrC's preview generation mechanism.

Overview of Photo View display methods:

| Method | Platform | Speed<sup>3</sup> | Reliability | Live Updates | Markings |
|----------|----------|----------|----------|----------|----------|
| Direct View | macOS, Windows<sup>1</sup> | Fastest | Best | Yes | Only corners | 
| Preview Image | Windows, macOS<sup>2</sup> | Fast | Good | No | Rectangles, clearly visible |
| Exported Image | Windows, macOS<sup>2</sup> | Slower | Best | No | Rectangles, clearly visible |

<sup>1</sup> Currently experimental on Windows due to a Lightroom SDK issue affecting transparent overlays.
<sup>2</sup> Not yet implemented on macOS
<sup>3</sup> Actual performance depends on image size, preview availability and system performance (CPU, GPU and disk speed). Users can choose the display method that best suits their workflow and hardware.
